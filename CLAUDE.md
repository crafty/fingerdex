# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FingerDex (https://fingerdex.org) is a static, client-only directory of fingerboarding brands and creators. There is no backend, API, or database: all data is hardcoded in the source and the site is deployed as a static Vite build.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — type-check (`tsc -b`) then production build to `dist/`
- `npm run lint` — ESLint
- `npm run preview` — serve the built `dist/`

There is no test suite. Use `npm run build` to verify changes, since it is the only step CI runs before deploying.

## Deployment

Every push to `main` triggers `.github/workflows/deploy.yml`, which runs `npm ci && npm run build` (Node 22) and publishes `dist/` to GitHub Pages. A broken build on `main` blocks the deploy, and a passing push to `main` goes live.

## Architecture

- **Data lives in `src/helpers/constants.tsx`.** `BRANDS_CREATORS` is a large `Creator[]` literal and makes up most of the codebase. Most commits are edits to this array ("updated creators"). The `Product` union type and the `PRODUCTS` array must stay in sync. Adding a new product category means updating both.
  - `Creator` fields: `name` and `instagram` are both nullable, and either one can identify a creator. Code falls back with `creator.name || creator.instagram`. `products: []` means the entry is not yet filled in.
- **Ordering:** `sortCreators` in `src/helpers/utilities.tsx` runs once at module load in `App.tsx`. It puts `promoted` entries first, then "Null FB", then entries with both website and products, then entries with only products, then empty entries.
- **Filtering:** `App.tsx` filters the sorted list by `searchQuery`, which matches against name or instagram, and by `selectedTags`. A creator must have every selected tag (AND logic). Both values live in a small Zustand store (`src/store/filtersStore.tsx`), which the search and filter components share. Clicking a product tag on a `CreatorCard` adds that tag to the filter.
- **Instagram data:** `mergeInstagramData` (utilities) adds `followersCount`, `private`, `latestPostTimestamp` and `profilePicUrlHD` to creators from `src/helpers/instagram-profiles.json`, matching on the lowercased handle without `@`. That JSON is generated by `npm run trim-dataset` from the git-ignored raw scraper export `dataset_instagram-scraper.json`. Never import the raw export into the app, because it's tens of MB. `profilePicUrlHD` always points at the self-hosted `/avatars/<username>.jpg`, generated by `npm run avatars`. Instagram's CDN blocks cross-origin image loads, so never hotlink it.
- **"Add creator" submissions** (`components/addCreator.tsx`) only build a `mailto:` link. There is no submission backend; new entries are added to `constants.tsx` by hand.
- **Analytics:** `index.html` injects Google Analytics (gtag), and `trackBrandClick` sends `brand_click` events when someone clicks a card link.
- `PAGES` drives the nav menu, but only "creators" is enabled. Resources and Events are placeholders.

## UI stack

- React 19 with the **React Compiler** enabled through a Babel preset in `vite.config.ts`, so manual `useMemo`/`useCallback` is usually unnecessary.
- **PrimeReact v11 (`@primereact/ui`)** components are imported per component, for example `@primereact/ui/button`. The theme is Aura, set up in `main.tsx` with dark mode keyed to the `.app-dark` class. This is the newer v11 API (`Menu.Root`, `Menu.Trigger`, the `toast` from `@primereact/ui/toaster`), not the classic PrimeReact API.
- Tailwind v4 is loaded through `@tailwindcss/vite`. Some classes use the `!` important suffix (for example `hidden!`) to override PrimeReact styles.
- Icons come from `@primeicons/react`.
- ESLint allows `@ts-expect-error` comments, which the code uses for the global `gtag`.
